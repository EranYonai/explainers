Why did the same test pass, then fail, with no code change?

Green yesterday, red this morning, green again when you rerun it. Nothing changed in the code, so something else is deciding the result.

The code never changed. The timing did, and the test was measuring the timing.

The fix is to wait for the thing itself: join the thread, await the result, or poll until the condition is true. Retries make the dashboard green but leave the race in place, and users can't rerun production.

Other causes with the same shape

  • Shared state. One test leaves a row, a file or a global behind, and another test reads it.
  • Test order. A test passes only when another one ran first. Shuffle the suite and it breaks.
  • The real clock. Code that reads the time fails near midnight, at month end, or on a server set to UTC.
  • The network. A call to a real service inherits its slowness and outages.

When one does flake, move it out of the blocking checks, give it an owner and a deadline, and count every pass-after-retry so you know which test to fix first.
